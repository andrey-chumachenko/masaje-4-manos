# Бот отзывов Masaje 4 Manos

Бот принимает JPG/PNG в личных сообщениях от разрешённых Telegram ID. Каждый скриншот становится отдельным черновиком. Оригинальные байты сохраняются в приватной D1; наружу доступны только отзывы, которые владелец подтвердил кнопкой **«Опубликовать»**.

## Как пользоваться

1. Откройте [@Masaje4ManosReviewsBot](https://t.me/Masaje4ManosReviewsBot) и нажмите «Запустить».
2. Отправьте скриншот. Для сохранения исходного качества отправляйте его как файл.
3. Дождитесь распознанных сообщений клиента и текстов на русском, испанском, английском и украинском.
4. При необходимости нажмите «Исправить», выберите язык и ответьте полным новым текстом на сообщение бота. Меняется только выбранный текст; остальные переводы нужно проверить в новом предпросмотре.
5. Нажмите «Опубликовать» под актуальным предпросмотром. Старая кнопка после исправления не работает.
6. Бот подтвердит публикацию только после появления отзыва и точной копии изображения на сайте.

`/drafts` показывает последние десять отзывов. `/preview ID` повторно показывает готовый черновик и делает прежние кнопки неактуальными. `/cancel` отменяет режим исправления. «Пропустить» оставляет отзыв вне сайта.

Если язык исходных сообщений определён неверно, нажмите «Язык оригинала». Выбор языка обновляет предпросмотр и отменяет старые кнопки подтверждения.

При нескольких скриншотах каждый проверяется и подтверждается отдельно. Облачная очередь обрабатывается раз в минуту, поэтому предпросмотр и обновление сайта могут занять несколько минут. Компьютер владельца для работы бота не нужен.

## Устройство

- `src/index.ts`: защищённый Telegram webhook, облачный таймер.
- `src/handlers.ts`: проверка владельца, команды, исправления и подтверждение версии.
- `src/ai.ts`: распознавание клиентских сообщений и четыре языка через Responses API; `store: false` и строгая JSON-схема.
- `src/github.ts`: атомарный коммит изображения, `src/data/generated-reviews.json` и `public/reviews-release.json`. Обновление ветки только fast-forward, с повторным чтением данных при конфликте.
- `src/jobs.ts`: очередь, лимит API-запросов, проверка фактической публикации.
- D1 хранит черновики, изображения отдельными бинарными блоками, входящие события и очередь уведомлений. Приватного HTTP-доступа к черновикам и изображениям нет.
- После подтверждения GitHub запускает существующую сборку Cloudflare Pages. На главной и `/opiniones` новые отзывы отображаются первыми.

Скриншоты и их содержимое считаются недоверенными данными. Модель не получает инструментов и не может публиковать: её ответ проходит проверку схемы, а код публикации требует сохранённую подтверждённую версию.

## Доступы

Секреты находятся в игнорируемом Git файле `.dev.vars` и в Cloudflare Worker Secrets. В код, Git и сообщения они не попадают:

- `TELEGRAM_BOT_TOKEN`: отдельный бот BotFather.
- `TELEGRAM_WEBHOOK_SECRET`: случайная строка для проверки источника webhook.
- `OPENAI_API_KEY`: API-ключ для распознавания и переводов.
- `GITHUB_TOKEN`: отдельный **fine-grained** токен аккаунта `andrey-chumachenko`, только для `masaje-4-manos`, `Contents: Read and write`. Общий токен GitHub CLI в облако не копируется.

Для безопасного локального ввода GitHub-токена:

```powershell
& 'H:\PROJECTS 2026\masaje-4-manos\review-bot\scripts\enter-github-token.ps1'
```

Токен вводится скрыто. После истечения его срока нужно ввести новый и повторить загрузку секретов. Токен не нужно отправлять в чат.

В `wrangler.jsonc` задаются Telegram ID администраторов, репозиторий, модель и лимит. По умолчанию разрешён только аккаунт владельца, до **10 запросов распознавания в день UTC**, изображения до **5 МБ**, тексты до **6000 символов** на язык. Дневной лимит ограничивает число запросов, а не сумму в долларах. Исправление перевода вручную не вызывает модель.

## Локальная проверка

```powershell
npm ci --prefix review-bot
npm test --prefix review-bot
npm run build
npm run lint
```

Тесты запускают Miniflare с настоящей локальной D1. Telegram, OpenAI, GitHub и сайт подменены: тесты не тратят API-кредиты и не публикуют отзывы.

## Развёртывание

Конфигурация содержит отдельную базу `masaje-review-bot` в существующем аккаунте Cloudflare. Для другого аккаунта сначала создайте новую D1 и замените `account_id` / `database_id`.

```powershell
Set-Location 'H:\PROJECTS 2026\masaje-4-manos\review-bot'
node scripts/setup.mjs --check
node node_modules/wrangler/bin/wrangler.js d1 migrations apply masaje-review-bot --remote
npm run deploy
node scripts/setup.mjs --upload-secrets
node scripts/setup.mjs --webhook https://WORKER.workers.dev
```

Сначала опубликуйте сайт с поддержкой `generated-reviews.json`, затем включайте webhook. Настройка webhook требует заполненных секретов; незавершённая настройка не выдаётся за работающего бота.

`/health` проверяет, что Worker отвечает, и не раскрывает конфигурацию. Для проверки готовности API используйте `npm run check`.

## Восстановление после ошибок

- Telegram повторил webhook: `update_id` и уникальный идентификатор файла не создают второй черновик.
- Повторный скриншот: проверяются уникальный ID Telegram и SHA-256, включая существующие изображения сайта. Изменённые/пересжатые версии могут иметь другой хеш; окончательно проверяйте предпросмотр.
- Результат платного запроса неизвестен: автоматического повторного распознавания нет. Повтор возможен только отдельной кнопкой и расходует ещё один запрос в пределах лимита.
- Ответ Telegram на отправку потерян: сообщение не отправляется повторно автоматически; следующая кнопка публикации в этом предпросмотре не отправляется, пока все тексты не доставлены. Восстановите предпросмотр через `/preview ID`.
- Результат коммита неизвестен: следующий проход сверяет текущую ветку по стабильному ID и хешу, сохраняя единственную запись.
- Сборка сайта задерживается: бот сообщает задержку и продолжает проверку. Успех подтверждается публичным release-файлом и SHA-256 загруженного изображения.

Черновики и пропущенные изображения автоматически не удаляются. Учитывайте их при обслуживании базы; публикуемые изображения остаются в Git.
